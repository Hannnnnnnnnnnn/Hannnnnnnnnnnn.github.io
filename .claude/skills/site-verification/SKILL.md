# 검증 — 조용히 거짓말하는 것들 (전부 이 저장소에서 실제로 당함)

2026-11-22 CLAUDE.md 에서 원문 그대로 옮김 (CLAUDE.md 를 가볍게 유지하려고). Moved verbatim from CLAUDE.md on 2026-11-22.

## 배포 확인 — 상세

**실패한 빌드는 아무것도 알려주지 않는다.** `error.message`는 `"Page build failed."`
한 줄이고 `duration`은 `0`이다. API에 더 이상의 정보가 없으니, Jekyll을 정말 도입해야
한다면 로컬에서 재현하는 수밖에 없다.

**초록색 push는 배포 완료가 아니다.** 실제로 이 저장소에서 push 결과만 보고 "라이브
반영됨"이라고 보고했다가 틀렸다 — 그때 라이브는 두 커밋 전 버전이었다. 순서:

1. 빌드 상태를 **묻는다** (폴링 루프로 기다리지 말고) —
   `gh api repos/Hannnnnnnnnnnn/Hannnnnnnnnnnn.github.io/pages/builds --jq '.[] | "\(.commit[0:7])\t\(.status)\t\(.duration)"'`
   성공한 빌드는 40초 안팎(`dur≈40000`)이 걸린다. `dur=0`이면 시작도 못 한 실패다.
2. 실제 파일을 받아 **로컬과 바이트 대조**한다. 바이트가 다르면 배포가 안 된 것이다.
3. 신·구 버전을 구분하는 **마커**로 확인한다 (예: 신 `class="display"` / 구 `class="cards"`).
   "status 200"은 옛 버전을 받았을 때도 나온다.

**GitHub 웹 에디터로 고쳐도 즉시 반영되지 않는다 — 같은 빌드를 탄다.** 웹 편집도 결국
커밋이므로 push 와 완전히 같은 경로다. 실측(2026-08-31): 커밋 `21:16:42Z` → 빌드 완료
`21:17:04Z` = **22초**. 그 뒤에도 화면이 그대로면 대개 **브라우저 캐시**이지 배포 실패가
아니다 — 하드 리로드나 `?cb=<timestamp>` 로 확인해라. 빌드 상태를 물어보면 둘이 바로
갈린다: `built`면 캐시 문제, `dur=0`이면 진짜 실패다.

**소유자가 웹에서 편집 중일 수 있다 — push 가 거부되면 원격부터 읽어라.** 2026-08-31 에
소유자가 히어로를 웹에서 고치는 동안 세션도 같은 파일을 고쳐 non-fast-forward 로 거부됐다
(`Update index.html` 은 웹 에디터의 기본 커밋 메시지다). 그때 확인한 것은 **두 수정의
diff** 였고 완전히 비어 있어서 로컬 중복 커밋을 버리고 `reset --hard origin/main` 하면
끝이었다. **`--force` 는 답이 아니다** — 내용이 달랐다면 소유자의 편집을 조용히 지웠을 것이다.

## 검증 함정 1–30

1. **`curl`이 `status=000`이면 사이트가 죽은 게 아니라 셸의 `CURL_CA_BUNDLE`이 깨진 것.**
   `~/.zshrc`에 없는 파일을 가리키는 값이 남아 있고, 오래된 세션은 그 값을 상속한다.
   항상 `env -u CURL_CA_BUNDLE curl ...`로 우회하고, `status`와 `bytes`를 같이 출력해라.
2. **404 페이지는 약 9KB짜리 HTML이고 grep을 통과한다.** 아직 배포되지 않은 파일을 받으면
   `main.js`가 9378바이트로 돌아오는데(로컬은 4114) 마커 grep은 그냥 0을 반환한다.
   "0 matches → 코드가 없다"가 아니라 "애초에 그 파일을 받지 않았다"이다.
   **바이트 수를 먼저 대조하고, 알려진 마커가 있는지 확인한 뒤에** 결론을 내라.
3. **숨겨진 자동화 탭에서는 IntersectionObserver 가 아예 발화하지 않는다.** 초기 콜백조차
   오지 않아서 "관찰자가 고장났다"로 읽히지만, 실제로는 프레임이 그려지지 않아 전달이
   보류된 것이다. 스크린샷을 한 장 찍으면 프레임이 강제되어 그때 밀린 콜백이 들어온다.
   섹션 가이드나 스크롤 리빌을 검증할 때는 **스크롤 → 스크린샷 → 상태 읽기** 순서로 해라.
   같은 이유로 `scroll-behavior: smooth` 가 걸린 페이지에서는 `scrollTo` 가 움직이지
   않는다 — 검증 전에 `document.documentElement.style.scrollBehavior = 'auto'` 로 꺼라.
   그리고 `loading="lazy"` 이미지도 로드되지 않는다.
4. **브라우저 자동화 탭은 `visibilityState: 'hidden'`이라 CSS 트랜지션·애니메이션·rAF가
   돌지 않는다.** `is-in` 클래스는 붙었는데 `getComputedStyle`의 opacity는 계속 0으로 읽힌다 —
   코드는 멀쩡한데 고장난 것처럼 보인다. 최종 상태를 보려면 강제 종료:
   `document.querySelectorAll('*').forEach(el => el.getAnimations().forEach(a => a.finish()))`
5. **렌더된 스크린샷이 최종 판정이다.** `mix-blend-mode` 같은 합성 효과는 computed style로
   확인이 안 된다. 화면을 찍어서 봐라.
6. **검사기가 통과했다고 검사한 게 아니다.** 안전망을 넣었으면 일부러 던져서 발동하는 것을
   확인해라 (`run(() => { throw new Error('test') })` → `html.js`가 떨어지고 콘텐츠가 보이는지).
   **반대도 성립한다 — 빨간불이 켜졌다고 코드가 틀린 것은 아니다.** `'감쇠' not in js` 로
   삭제를 확인하려다 잉크 획의 "지수 감쇠"와 행 미리보기의 "따라오는 감쇠"에 걸렸고,
   HTML 중첩 검사기는 `<path/>` 를 self-closing 으로 처리하지 못해 인라인 SVG 를 전부
   mismatch 로 떨어뜨렸다. 둘 다 검사기가 틀린 것이다. **FAIL 을 보면 코드를 고치러 가기
   전에 검사기부터 의심해라** — 멀쩡한 것을 망가뜨리게 된다.
7. **상관관계를 원인이라고 부르지 마라 — 이 저장소에서 5번째 데이터가 4번째까지를
   뒤집었다.** Pages 빌드 실패를 조사하다 "소유자가 트리거한 빌드만 성공하고
   collaborator가 푸시한 건 전부 0ms로 실패"라는 완벽한 상관을 4건에서 찾아 원인으로
   단정했다. 바로 다음 빌드가 collaborator 푸시로 성공하면서 가설이 무너졌다.
   진짜 원인은 Jekyll 처리 단계였다. 표본이 적을 때 "결정적"이라는 말을 쓰지 말 것.
8. **좁은 폭 검증은 iframe으로 한다 — 브라우저 자동화의 창 크기 변경은 no-op이다.**
   폭을 지정한 iframe은 자체 뷰포트를 가지므로 `vw`·`clamp()`·미디어쿼리가 그 폭 기준으로
   계산된다. 320/360/390/768/1280을 이렇게 실측했다.
   **단 포인터 종류는 못 바꾼다.** iframe 안에서도 `(hover: hover) and (pointer: fine)`은
   호스트 기기를 따라 참으로 나오므로, 그 미디어쿼리에 걸린 기능(커서 블롭, 감쇠 스크롤)이
   "모바일에서도 켜진 것처럼" 보인다. 레이아웃 검증에만 쓰고 입력 방식 검증에는 쓰지 마라.
   **그리고 헤드리스 스크린샷으로는 대신할 수 없다 — 창을 500px 밑으로 못 내린다.**
   `--window-size=390,1500` 은 500px 로 렌더한 뒤 이미지를 390 으로 **자를** 뿐이라, 500px
   기준으로 줄바꿈된 텍스트가 잘려 보이고 레이아웃이 깨진 것처럼 읽힌다. 실제로 이 거짓
   실패를 한 번 믿었다가 iframe 실측(`overflow=0`)과 충돌해서야 알았다. 판정이 갈리면
   페이지에 측정 스크립트를 심어 `innerWidth` 를 직접 찍어라 — 그게 셋째 증거다.
9. **시간에 따라 변하는 동작은 이 환경에서 검증할 수 없다 — 우회로도 막혀 있다.**
   숨은 탭은 rAF 를 아예 돌리지 않는데, `requestAnimationFrame` 을 `setTimeout` 으로
   갈아끼우는 우회도 통하지 않는다. 백그라운드 탭은 타이머도 초 단위로 스로틀하므로 한
   "프레임"이 1초가 되고, 480ms 짜리 궤적은 그 사이 전부 만료된다. 실제로 이 방법으로
   커서 궤적을 검증하려다 `gradientCount: 1, opacity: 0` 이라는 **정상 코드에 대한 거짓
   실패**를 얻었다.
   할 수 있는 것: 그 시점에 만들어질 상태를 **직접 구성해서** 화면으로 확인하는 것.
   할 수 없는 것: 추적감·감쇠·지속시간. 그건 실제 브라우저에서 사람이 봐야 하고,
   "검증했다"고 말하면 안 된다.
10. **타이밍 의존 코드는 `performance.now` 를 직접 통제해서 결정적으로 재현한다.**
   8번의 제약(스로틀) 때문에 실제 지연을 넣는 테스트는 무의미하다 — 26회 반복이 수십 초가
   되어 수명 620ms 짜리 자국이 전부 만료됐고 `inkPixels: 0` 이라는 거짓 실패가 나왔다.
   대신 `performance.now = () => (t += 26)` 로 호출마다 고정 시간을 전진시키고, rAF 콜백은
   `window.requestAnimationFrame = (fn) => { pending = fn }` 로 붙잡아 뒀다가 한 번만
   수동 실행한다. 이러면 속도 기반 로직까지 정확히 원하는 값으로 재현된다.
11. **"이어져 있는가" 같은 성질은 눈이 아니라 픽셀로 재라.** 캔버스를 가로로 훑어 잉크가
   있는 열과 그 사이 최대 빈 구간을 세면(`maxInternalGapPx`) 획이 끊겼는지 즉시 나온다.
   스크린샷으로는 "대충 이어져 보인다"까지밖에 말할 수 없다.
12. **충돌 검사는 두 축을 모두 봐야 한다.** 행 제목이 길어졌을 때 메타와 겹치는지 재면서
   가로 범위만 비교했다가 320·390px 에서 거짓 양성을 얻었다. 그 폭에서는 미디어쿼리가 메타를
   **아래 줄로 내리므로** 세로가 겹치지 않는다. `xOverlap && yOverlap` 이어야 실제 충돌이다.
13. **세로로 긴 스크린샷은 `sips -Z` 로 줄이면 못 읽는다.** `-Z` 는 **긴 변** 기준이라
   1280×7000 짜리 페이지가 가로 200px 로 뭉개진다. PIL 로 **겹치게 밴드를 잘라**
   가로 900 안팎으로 리샘플할 것 — 겹침이 있어야 문맥이 끊기지 않는다.
14. **"몇 개 보이나"를 `clientWidth / 카드폭` 으로 재면 패딩만큼 거짓말한다.** 가로 스크롤
   레일에서 이 식이 390px 기준 `2.19개`를 냈는데 화면에는 정확히 2개, 걸치는 카드가
   **0px** 이었다 — `clientWidth` 는 좌우 패딩을 포함하기 때문이다. 걸침은 이 컴포넌트가
   스크롤된다는 **유일한 신호**라서, 그게 0이면 기능이 멀쩡해도 아무도 스크롤하지 않는다.
   재려면 카드의 `getBoundingClientRect()` 를 레일의 가시 영역과 직접 교차시켜라.
   그리고 **한 폭만 재지 마라** — 고정 카드폭은 특정 뷰포트에서 딱 맞아떨어지는 지점이
   생기고, 하필 그게 가장 흔한 폰 폭이었다. 320~1600 을 훑어 걸침이 0 이 되는 폭이
   없는지 확인할 것. 해법은 비율(`clamp(108px, 40%, 132px)`)로 그 우연을 없애는 것이다.
15. **iframe 은 HTTP 캐시를 그대로 쓴다 — 편집 직후 측정하면 편집 전 DOM 을 잰다.**
   값 span 의 대시를 en dash 로 바꾸고 폭 5개를 훑었더니 다섯 개 전부 옛 문자를 돌려줬다.
   파일과 서버 응답에는 새 값이 들어 있었으니 **코드가 아니라 측정이 틀린 것**이었다.
   `src` 에 `?cb=` + 타임스탬프를 붙여라. 헤드리스 스크린샷은 새 프로세스라 이 함정이
   없어서, 스크린샷과 iframe 측정이 어긋나면 iframe 쪽을 먼저 의심하면 된다.
16. **실물과 대조할 땐 뷰포트를 여러 개 찍어라 — 칼럼이 유동이면 한 폭의 값은 값이 아니다.**
   PDP 상품 칼럼은 1280 에서 402px, 1440 에서 466, 1600 부터 530 으로 고정된다. 500px
   자동화 탭에서 잰 스워치 64x85 를 그대로 믿었으면 데스크톱 재현이 통째로 틀렸을 것이다
   (실제 값은 76x101). 크로스오리진이라 `contentDocument` 가 막히면 **렌더된 픽셀에서
   직접 재라** — 흰 거터를 찾아 타일 폭·간격을, 글자 잉크 높이로 font-size 를 역산할 수 있다.
17. **주석에 적힌 "라이브에서 잰 값"을 믿지 말고 다시 재라 — 유통기한이 있다.**
   `style.css` 에 "실제 칼럼은 520px, 스워치 5개가 한 줄에 선다"가 적혀 있었는데 실물은
   1600px 에서 530px 에 한 줄 6개였고, 게다가 `max-width` 는 padding 을 포함하므로
   `32rem` 은 내용 폭을 456px 로 만들고 있었다. 값 네 개가 틀린 채로 배포돼 있었다.
   **뷰포트를 함께 적지 않은 치수는 절반이 거짓말이다.** 새로 적을 때는 어느 폭에서
   쟀는지, 유동이면 어디서 고정되는지까지 남겨라.
18. **선언이 안 먹으면 규칙을 고치기 전에 무엇이 이기고 있는지 뽑아 봐라.** 한 세션에 세 번
   당했다: `figure.figure`(요소+클래스)가 `.figure--diagram`을, `.frame--mobile .frame__scroll`
   (클래스 2개)이 `.frame__scroll--video`를 이겼고, 내가 직접 넣은 `align-items: start`가
   배치가 의존하는 stretch를 막고 있었다. 증상은 셋 다 "규칙을 썼는데 반영이 안 된다"이다.
   그때 규칙을 고쳐 쓰지 말고 매칭되는 것을 전부 뽑아라 —
   `for (const r of sh.cssRules) if (el.matches(r.selectorText)) …`.
   **그래도 원인을 못 찾으면 그럴듯한 설명을 지어내지 말고 값을 명시하고 "미확인"이라고 적어라.**
19. **그리드에서 한 칸이 행 높이에 참여하면 안 될 때는 `minmax(0,1fr)` 로 부족하다 —
   absolute 여야 한다.** `1fr` 은 자동 최소 크기를 내용에서 가져오므로 3845px 이미지가
   전혀 줄지 않았고, `minmax(0,1fr)` 로 트랙을 줄여도 창이 그 높이를 행에 기여해 옆 칸보다
   279px 길어졌다. `position:absolute; inset:0` 인 스크롤러만이 높이에 기여하지 않는다.
20. **재현은 한 축만 재고 끝내면 반드시 틀린다.** 리뷰 아코디언에서 summary 높이 46px 은
   정확히 맞췄으면서 **별 색은 재지도 않았다** — 실물은 `#f5a623` 을 `#dcdcdc` 위에

   구분선(실제 1px `#0c0c0c`)을 연회색으로, 마커(실제 캐럿 SVG)를 `+/−` 로 만들었다.
   **치수·색·자간·내용·상태를 각각 따로 재라.** "테마에서 읽어왔다"는 그중 하나만 읽었다는
   뜻이기 쉽다.
21. **미디어 인코딩 폭은 소스가 아니라 그 요소의 최대 렌더 폭 × 2 다.** 데스크톱 히어로를
   1440 으로 뽑았다가 1280 으로 낮췄다 — 그 프레임은 어떤 화면에서도 625 CSS px 를 넘지
   않는다(실측). 소유자 녹화는 120fps 라 그대로 쓰면 18.9MB·234MB 다. 항상 다시 인코딩:
   `-vf scale=<폭>:-2,fps=30 -crf 27~31 -movflags +faststart -an`. 그리고 **배경 텍스처를
   넣을 땐 그 위의 가장 작은 muted 글자부터 확인해라** — 큰 글자는 어차피 살아남는다.
22. **`scrollWidth > clientWidth` 가 false 라고 잘 읽히는 것은 아니다 — flex 자식은 넘치는
   대신 문구를 쪼갠다.** 320px 에서 임팩트 카운터가 "오버플로 없음"으로 통과했는데, 실제로는
   숫자와 단위가 한 줄에 못 들어가 `"bottles upcycled"` 만 두 줄로 쪼개져 숫자 옆에 걸쳐
   있었다. flex item 은 기본 `flex-shrink: 1` 이라 폭이 모자라면 넘치지 않고 안의 텍스트를
   줄바꿈하므로 오버플로 검사가 조용히 통과한다. **오버플로 검사는 "깨졌는가"만 잡고
   "읽히는가"는 못 잡는다** — 좁은 폭에서는 줄이 어디서 끊기는지를 눈으로 확인해라.
   항목 단위로 넘기려면 `flex-wrap: wrap`.
23. **작업을 시작하기 전에 `git fetch` 하고 `HEAD..origin/main` 을 세라 — 이 클론은 조용히
   뒤처진다.** 2026-08-31 에 **32커밋** 뒤처진 트리 위에서 한 시간을 썼고, `git push` 가
   거부되고서야 알았다. 그 사이 원격에서는 `work-1` 이 PLP → **PDP** 로 바뀌고 PLP 는
   `work-2` 로 옮겨갔으며, 히어로 영상 프레임과 index 행 호버 미리보기가 이미 들어와
   있었다 — **엉뚱한 페이지를 고치고 있는 기능을 다시 만들었다.** 다시 하니 30분이
   안 걸렸다(있는 컴포넌트에 얹기만 하면 됐다).
   **소유자가 이 저장소에 없는 페이지·기능을 언급하면 오타로 넘기지 마라.** "PDP revamp 와
   같이"라는 말이 정답을 정확히 가리키고 있었는데, 로컬에 그 페이지가 없다는 이유로 무시했다.
24. **"없다"는 결론은 "있다"보다 검증이 더 필요하다 — 정적 HTML 은 JS 가 만드는 상태를
   말해 주지 않는다.** 라이브 PLP 를 받아 카드 19개 전부 `.card-information__button` 이
   비어 있는 것을 보고 "카드에 add to cart 가 없다"고 보고했다. 소유자가 바로잡았다:
   스워치에 **mouseenter** 하면 `color-swatches.js` 가 `?variant=<id>&view=card` 를 fetch 해
   그 슬롯을 채우고(`updateButtons()`), 그다음 `.card-wrapper:hover` 가 버튼을 올린다.
   **초기 마크업 · 서버 응답 · 실행 중 DOM 은 서로 다른 세 개의 문서다.** 그 저장소의
   컴포넌트 JS 를 한 번 읽거나 실제로 호버해 보는 데 1분이면 됐다.
   같은 실수의 연장으로 **버튼 색도 틀렸다** — 레포에 있던 `.pdp__cta`(흰 배경/검은 테두리)를
   재사용했는데 그건 PDP 의 아웃라인 버튼이고, 카드의 것은 기본 `.button` 이라
   `--color-base-accent(12,12,12)` 배경에 `--color-base-solid-button-labels(255,255,255)`
   글자였다. **레포의 기존 값을 재사용하는 것과 그 값이 여기에도 맞는지 확인하는 것은
   다른 일이다** — "라이브에서 잰 값"이라는 주석은 *어디서* 쟀는지까지 적혀 있어야 믿을 수 있다.
25. **프리뷰 쿠키는 몇 달이 지나도 따라온다 — 라이브를 봤다고 말하기 전에 `Shopify.theme.role`

   `role: unpublished`)를 서빙하고 있었다. `themes(roles:[MAIN])` 로 현재 라이브를 확인하고
   `?preview_theme_id=` 를 명시해도 Markets 리다이렉트(.com → .ca)에서 파라미터가 떨어진다.

26. **`[hidden]` 은 클래스 규칙의 `display` 에 진다.** `.demo .pcard__corner{display:grid}`
   (0,2,0) 가 UA 의 `[hidden]{display:none}` (0,1,0) 를 이겨서, 토글이 **아무것도 숨기지
   못했다**. 증상이 고약한 것은 "토글이 안 먹는다"가 아니라 **켠 상태가 기본으로 보이는**
   것이라 JS 를 먼저 의심하게 된다는 점 — `el.hidden === true` 를 읽고도 화면에는 있었다.
   `:not([hidden])` 로 스코프할 것. 함정 18 의 또 다른 사례다.
27. **인코딩 폭의 "최대 렌더 폭"을 데스크톱에서 찾지 마라 — 반응형 컴포넌트는 좁은 폭에서
   오히려 커진다.** 배너를 데스크톱 렌더 폭(358px)의 2배인 720 으로 뽑았는데, `.cmp` 는

   폭을 정하기 전에 320~1280 을 훑어 렌더 폭의 최대값을 실측할 것.

28. **`200` + 올바른 `Content-Type` 이 파일을 받았다는 뜻이 아니다 — SPA 는 아무 경로에나
   에러 페이지를 200 으로 준다.** 로고를 받으려고 `claude.ai/favicon.svg` 를 쳤더니
   `status=200`, `Content-Type: image/svg+xml`, 60KB 가 왔다. 본문은 Next.js 에러 HTML 이었다
   (`claude.ai/icon.svg` 도 107KB 로 같은 결과). **상태 코드·확장자·MIME 이 전부 맞는데
   파일이 아니다** — 404 를 상태 코드로 거르는 함정보다 한 단계 어렵다. 바이너리·에셋을
   받았으면 `head -c 4` 로 매직 바이트를 보라(`<svg`, `\x89PNG`). 한 줄이고, 이번에 두 번
   걸렸다.
   **더 조용한 실패도 같이 나왔다: 형식이 맞는 "틀린 물건".**
   `anthropic.com/.../safari-pinned-tab.svg` 는 진짜 SVG 라 모든 형식 검사를 통과하지만
   Claude 마크가 아니라 Anthropic 워드마크다. **렌더해서 눈으로 봐야 안다.**
   형식이 맞는 것과 맞는 물건인 것은 다르다 — 애셋을 자동으로 긁어올 때는 마지막에
   반드시 한 번 그려서 확인할 것.

29. **로컬 서버는 열릴 수도 있고 안 열릴 수도 있다 — 기억하지 말고 매번 한 번 열어 봐라.**

    적어 뒀는데, **2026-09-17 에는 `localhost:8777` 과 `127.0.0.1:8777` 둘 다 정상적으로
    열렸고** 페이지 안에서 JS 측정까지 됐다. 확장 권한은 머신·버전·설정마다 다르므로 이 항목은
    "된다/안 된다"가 아니라 **확인 절차**다: 한 번 navigate 해 보고, 죽으면 아래 우회로 간다.
    여전히 막힌 것은 `file://` 이다 (`Can't interact with browser-internal or unparseable URLs`).
    **우회: 이미 배포된 페이지에 새 CSS/JS 를 주입해서 실렌더를 검증한다.** 배포 없이
    진짜 렌더 결과를 얻을 수 있어, "일단 올리고 본다" 보다 안전하고 빠르다 (2026-09-17,
    데모 C 호버를 이 방법으로 확인하고 배포했다).

30. **합성 `MouseEvent` 는 `:hover` 를 만들지 않는다 — CSS 호버는 자동화로 트리거할 수 없다.**

    `false` 이고 `getAnimations()` 는 빈 배열이다. 멀쩡한 호버 애니메이션이 "안 돈다"로
    읽히는데, 함정 4(숨은 탭이라 안 돎)와 원인이 다르다 — 이건 **상태가 아예 안 붙는 것**이라
    `finish()` 우회도 소용없다.
    **할 수 있는 것:** 같은 키프레임을 임시 클래스로 강제 적용해 키프레임이 해석되고
    재생되는지(`animationName`, `currentTime > 0`)까지 확인. **할 수 없는 것:** 호버 트리거
    자체 — 사람이 봐야 하고, "검증했다"고 말하면 안 된다 (2026-09-17, work-1 ATC 호버).

## 로컬 미리보기와 자동화 (2026-09-17 이전 기록 — 함정 29 가 더 최신이다)

**단 이 서버는 사람이 보는 용도다 — 브라우저 자동화(Claude in Chrome)는 `localhost` /

→ **자동화로 검증하려면 푸시해서 라이브 URL 에서 본다**(이 저장소는 push 가 곧 배포다).
그때 두 가지를 조심할 것:

1. **`curl` 바이트가 같아도 탭은 옛 CSS/HTML 을 쓰고 있다.** 실제로 "수정이 안 먹었다"로

   **특정 셀렉터가 실제로 로드됐는지** 먼저 확인하고, HTML 은 `?cb=` 를 붙여 재탐색한다.
2. **스크롤 리빌을 풀겠다고 `opacity:0` 을 전부 `1` 로 올리지 마라.** 의도적으로 투명한
