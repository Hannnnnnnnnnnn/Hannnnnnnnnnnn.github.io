### 세로로 긴 스크린샷을 읽는 법

원본이 1280×5553~7209px 라 그냥 축소하면 못 읽는다. **`sips -Z` 는 긴 변 기준**이라
세로가 긴 페이지에서는 가로가 200px 로 뭉개진다(실제로 그렇게 만들었다가 버렸다).
PIL 로 **겹치게 밴드로 잘라** 가로 900 으로 리샘플하는 방식이 통했다:

    im.crop((0, a, W, b)).resize((900, ...))   # a,b 를 겹치게 잡아 문맥 유지

## 채운 내용

원문은 **하나의 모듈러 시스템을 세 표면에** 전개한 구조였다 — Hero Banner(3 브레이크포인트),

(마케팅비를 매출의 약 14.3% 로 묶은 채 수천 개 터치포인트를 커버)을 그대로 썼다.

### 원문이 자기 자신과 모순됐다

결과 배너 그래픽과 바로 옆 본문이 다른 숫자를 말했다:

| | 배너 그래픽 | 본문 |
|---|---|---|
| 매출 YoY | +22% | +35% |
| 안경 수량 | 16,800개 (+35%) | 16,900족 (+47%) |

**임의로 고르지 않고 충돌하는 값을 일단 전부 뺀 채 올린 뒤 소유자에게 물었다.**
답: 배너 그래픽을 따른다. 최종 = $5.8M(+22%), 안경 $1.2M / 16,800개(+35%),
11월 안경 매출 +56%, 최초 $300M 런레이트, 재구매 기여 65%.

연도와 툴은 원문에 없어서 **지어내지 않고 비워둔 채 물었다** → 2025년,
Photoshop / After Effects / Veo 3.1.

## 배운 것

- **출처가 자기모순이면 조용히 고르지 마라.** 어느 쪽을 골라도 절반은 틀린 숫자가 되고,
  포트폴리오에서 틀린 숫자는 치명적이다. 빼고 묻는 편이 싸다.
- **없는 메타데이터를 지어내지 마라.** 연도·툴은 그럴듯하게 채울 수 있었지만 전부 오답이 될
  수 있었다(실제 툴에 After Effects 가 있었는데 추측했다면 못 맞혔다).
- **새 HTML 요소를 쓰면 스타일이 따라와야 한다.** `<blockquote>` 를 넣자 브라우저 기본
  들여쓰기로 떨어져 디자인과 어긋났다. 좌측 규칙선으로 대체.
- **충돌 검사는 두 축을 다 봐야 한다.** 제목이 길어져 좁은 폭 충돌을 쟀는데 가로만 비교해
  320·390px 에서 거짓 양성이 났다. 640px 이하에서는 메타가 아래 줄로 내려가 세로가 겹치지
  않는다. 두 축을 함께 보니 전 폭 충돌 0.
