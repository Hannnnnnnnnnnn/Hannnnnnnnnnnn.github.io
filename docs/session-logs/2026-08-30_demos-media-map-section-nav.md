## 1. 정확한 재현이 실패한 재현일 수 있다

배지를 두 번 만들었다.

**첫 번째**는 눈대중이었다. 흰 사각형에 테두리. 값이 어디서 왔냐면 아무 데서도 안 왔다.

**두 번째**는 Shopify MCP 로 라이브 테마의 블록 설정을 읽어서 맞췄다.
`graphql_query` → `theme(id:).files(filenames:)` 로 `templates/product.pdp-revamp_*.json` 을
받으면 배지 색·크기·임계값이 그대로 들어 있다. 브라우저로 실물 PDP 의 computed style 을
재는 편이 빠를 때도 있다. 얻은 값:

    low stock   #dc2626 / new #16a34a / popular #ea580c
    show_background: false      ← 그래서 라이브는 색 글자만 나온다
    PET 배지     #54d583, 접힘 알파 50% / 펼침 불투명, radius 30, padding 6/12

**접힘과 펼침의 색이 다른 것**은 눈으로는 절대 못 잡았을 것이다. 테마가
`--pet-badge-bg` 에만 알파를 씌우고 `--pet-badge-bg-hover` 에는 안 씌운다.

그런데 **두 번째도 실패했다.** 값은 전부 맞았는데 사용자의 답은 "아이콘만 옮겨놨네"였다.
회색 사각형 위에 뜬 알약은 장식으로 읽히고, 스켈레톤 막대 두 개 옆의 색 글자는 그게
무엇의 배지인지 말하지 않는다.

**교훈: 재현의 단위는 값이 아니라 대상이다.** 배지가 논증하는 게 "가장 비싼 자리를
덮는다"는 판단이라면 실제 상품 사진이 있어야 그 판단이 보인다. 배지가 제목 위에 앉는
컴포넌트라면 제목·가격·스워치·CTA 가 같이 와야 한다. 치수만 맞추고 맥락을 빼면
정확하면서 동시에 틀린 물건이 나온다.

세 번째에 상품 정보 칼럼을 통째로 가져왔고, 그때 **케이스에 없던 Popular 배지**가
드러났다. 세 배지가 자리 하나를 나눠 쓰고 Low Stock → New → Popular 순으로 먼저 맞는
것이 이긴다. 조각만 봤으면 끝까지 몰랐을 사실이다.

## 2. 숨겨진 자동화 탭에서 죽는 것들 — 목록이 길어졌다

`CLAUDE.md` 에 이미 "트랜지션·rAF 가 안 돈다"가 있었는데, 이번에 셋을 더 만났다.
전부 같은 원인이다: **프레임이 그려지지 않는다.**

1. **IntersectionObserver 가 아예 발화하지 않는다.** 초기 콜백조차 안 온다. 관찰자를
   새로 만들어 로그를 심어도 배열이 비어 있어서 "관찰자가 고장났다"로 읽힌다.
   스크린샷을 한 장 찍으면 프레임이 강제되고 밀린 콜백이 그때 들어온다.
   → 검증 순서는 **스크롤 → 스크린샷 → 상태 읽기**.
2. **`scroll-behavior: smooth` 가 걸리면 `scrollTo` 가 움직이지 않는다.** 애니메이션이
   안 도니까 위치가 그대로다. `scrollY` 를 같이 찍지 않았으면 "게이팅이 고장났다"고
   보고할 뻔했다. 실제로 한 번 그렇게 오진했다.
3. **`loading="lazy"` 이미지가 로드되지 않는다.** `naturalWidth` 가 0 이라 경로가
   틀렸다고 결론 낼 뻔했는데, `curl` 로는 200/16654 였다.

**공통 교훈: "안 된다"를 보고하기 전에 그게 코드인지 이 탭인지 먼저 갈라라.**
서버에서 `curl` 로 확인하고, 스크린샷으로 프레임을 강제하고, 좌표·크기를 같이 출력해라.

## 3. 자기가 만든 검사기를 믿지 마라

최종 점검에서 두 항목이 FAIL 로 떴다.

- `'감쇠' not in js` → main.js 201·291 줄의 "지수 감쇠"(잉크 획), "따라오는 감쇠"(행
  미리보기)에 걸렸다. 제거 대상과 무관한 정당한 용법이다.
- HTML 중첩 검사기가 `<path/>` 를 self-closing 으로 처리하지 못해 SVG 를 인라인하자
  전부 mismatch 로 떨어졌다.

둘 다 **코드가 아니라 검사기가 틀린 것**이었다. 정확한 마커로 바꾸니
(`addEventListener("wheel"`, `handle_startendtag`) 통과했다.
검사기가 빨간불을 켰을 때 코드부터 고치러 가면 멀쩡한 것을 망가뜨린다.

한편 검사기가 **진짜로 잡아준 것**도 있다: 데모 B 를 교체하면서 닫는 `</div>` 를 같이
먹었다. 눈으로는 안 보였고 렌더도 그럴듯했다.

## 4. 지우는 것이 고치는 것일 때

"스크롤이 뻑뻑하다"의 정체는 4번 블록의 감쇠 스크롤이었다. 휠 이벤트를 전부
`preventDefault` 하고 0.12 이징으로 따라가게 만든다.

**그 블록의 주석이 이미 답을 적어놨다** — "접근성 비용을 알고 넣은 것이다.
빼려면 이 run(...) 하나를 지우면 되고 나머지 동작에는 영향이 없다."
과거의 자신이 남긴 탈출구를 그대로 쓰면 됐다. main.js 가 25.6KB → 20.6KB 로 줄었다.

**교훈: 의도된 트레이드오프에는 탈출구를 주석으로 적어둬라.** 나중에 그 비용이 실제로
문제가 됐을 때 재조사 없이 되돌릴 수 있다. 이번에 그 값을 회수했다.

같은 맥락에서 **애니메이션이 안 돌면 콘텐츠가 사라지는 구조를 만들지 마라.**
결정 번호 펼침을 `@keyframes ... from { opacity: 0 }` 로 만들었는데, 백그라운드 탭에서
번호가 투명한 채로 굳었다. 높이 즉시 변경 + opacity 트랜지션으로 바꾸니 그런 상태가
아예 없어졌다. 값이 아니라 **실패 모드**를 보고 고르는 게 맞다.

## 5. 브라우저가 잡아낸 것들 (CSS 읽기로는 안 나왔다)

- **짝 프레임이 겹치지 않았다.** 모바일 프레임의 `margin-top` 이 컨테이너 밖으로
  상쇄돼 둘이 같은 높이에서 시작했다. `display: flow-root`.
- **"모바일" 프레임이 본문 폭까지 벌어져** 데스크톱 프레임처럼 읽혔다. 폭 제한.
- **세그먼트 컨트롤이 grid 폭까지 늘어나** 테두리만 남은 빈 상자가 됐다. `justify-self: start`.
- **앵커로 진입하면 목차가 비어 있었다.** 대상이 관찰 밴드 위에 착지해서 관찰자가
  한 번도 발화하지 않는다. hash 도착과 클릭에서 먼저 반영하게 했다.
- **스워치가 2줄로 접혔다.** 칼럼을 실제 폭(520px)으로 넓히니 5개가 한 줄에 섰다.

**전부 렌더를 봐야만 나오는 것들이다.** `CLAUDE.md` 의 "렌더된 스크린샷이 최종 판정"이
이번에도 다섯 번 맞았다.

## 6. 원고와 실물이 어긋난 자리 (미해결)

라이브 테마를 읽다가 케이스 원고와 다른 사실 두 개를 찾았다. **원고는 손대지 않았다** —
카피는 최종이고, 고칠지는 소유자가 정할 일이다.

| 원고 | 실제 |
|---|---|
| `pet_bottle_count` 메타필드 | `custom.pet_bottle_badge2` (그 이름의 필드는 없음) |
| low stock 임계값 2 | 라이브 설정은 1 |

데모 A 의 Liquid 발췌는 **페이지와 맞도록** `pet_bottle_count` 로 뒀다. 바로 옆 문단과
코드가 어긋나는 게 더 나쁘다고 봤다. 원고를 고치면 발췌도 같이 고쳐야 한다.

`BUILD-PLAN.md` §9 의 `buy-buttons.liquid` 로케일 분리도 미해결이다 — 그건 테마
저장소의 일이라 여기서 할 수 없고, 데모 C 발췌는 고친 뒤의 형태(`| t`)로 실려 있다.
