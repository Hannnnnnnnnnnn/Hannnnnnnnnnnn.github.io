## 숫자 전사는 눈이 아니라 토큰 대조로 검증했다

프로젝트 지침이 *"숫자를 지어내거나 반올림하거나 외삽하지 마라"* 이므로 전사 정확도가 곧
품질이다. 렌더된 HTML 에서 텍스트만 뽑아 숫자 토큰을 세고, 원본 마크다운의 토큰 다중집합과

세 파일 모두 **누락 0**. 이미지 슬롯 25개도 `assets.json` 의 경로 순서와 alt 문자열까지

## 헤드리스 Chrome 은 창 폭을 500px 미만으로 못 내린다

이번 세션에서 **가장 오래 속은 것.** `--window-size=390,1500` 으로 찍은 스크린샷에서 히어로
카피와 카드 서브라인이 오른쪽에서 잘려 보였다. 그런데 iframe 실측은 `overflow=0` 이었다.
둘 중 하나가 거짓말을 하고 있었다.

페이지에 측정 스크립트를 심어 같은 조건으로 렌더해 보고 원인이 나왔다:

    viewport=500 docScrollW=500 bodyScrollW=500     # --window-size=390 으로 띄웠는데

**헤드리스는 창을 500px 로 올려 렌더하고, 스크린샷만 390 으로 잘라 준다.** 그래서 500px 폭
기준으로 줄바꿈된 텍스트가 390 크롭에서 잘려 보인 것이다. 레이아웃은 멀쩡했다.

기존 함정 7번(자동화의 창 크기 변경은 no-op → iframe 을 써라)과 같은 계열인데, 헤드리스
스크린샷은 **그럴듯한 이미지를 돌려주기 때문에 더 위험하다.** no-op 은 눈치채기라도 쉽다.

## 호버 미리보기 — 루프를 짜기 전에 트랜지션을 먼저 의심하라

커서를 감쇠하며 따라오는 미리보기 창을 rAF 루프 + lerp 로 짤 뻔했다. `transform` 에
트랜지션을 걸고 **목표 좌표만 바꾸면** 이징이 감쇠를 그대로 대신한다. 루프도, 상태 변수도,
정지 조건도 필요 없다.

    transform: translate3d(var(--x), var(--y), 0) scale(1);
    transition: transform 0.45s cubic-bezier(0.16, 1, 0.3, 1);

대신 **첫 등장은 트랜지션을 끈 채 배치해야 한다.** 안 그러면 직전 행에 있던 위치에서
날아온다. `is-placing` 클래스로 `transition: none` → 좌표 설정 → 리플로우 강제 → 클래스 제거.

검증은 합성 이벤트로 했다. `mouseenter`/`mousemove` 를 직접 디스패치하고
`getAnimations().finish()` 로 최종 상태를 굳힌 뒤 위치·클래스·화면 안 여부를 읽었다:

| 상태 | 결과 |
|---|---|
| 1번 행 호버 | 커서 +20,+20, `01-pdp/01.jpg` |
| 3번 행으로 이동 | 이미지 교체됨 |
| 커서를 화면 모서리로 | 뷰포트 안으로 접힘 |
| 벗어남 | `opacity 0`, `scale 0.92` |
| 페이지 넘침 | 0 |

**감촉·지속시간은 검증하지 않았고 검증했다고 말하지도 않았다** — 함정 8번 그대로다.

## 이미지가 없는 기능을 어떻게 내보낼 것인가

미리보기의 대상인 히어로 이미지 3장이 전부 404 다(25개 슬롯 전체가 아직 비어 있다).
**깨진 이미지 아이콘 대신 케이스 페이지가 이미 쓰는 회색 자리표시로 떨어지게** 했다 —
`onerror` 면 `is-loaded` 를 안 붙이고, 그 상태에서는 슬롯 캡션이 보인다. 파일을 넣으면
코드 수정 없이 사진으로 바뀐다.

자리표시에 **경로를 그대로 찍어 두는 것**도 같은 생각이다. 다만 `.label` 이 대문자로 바꿔서
`/IMAGES/01-PDP/01.JPG` 로 보였다 — 파일명에 대해 거짓말하는 셈이라 `<code>` 로 감싸
그 칸만 대문자 변환을 되돌렸다.

## 이메일 한 줄이 320px 를 밀어냈다

About 에 연락처를 넣자 그 페이지만 320px 에서 `overflow=10` 이 났다.
`hanbyoul.kim91@gmail.com` 은 **끊을 자리가 없는 한 덩어리**라 `.meta` 의 `1fr` 칸을
자기 폭만큼 밀어낸다. `.meta dd { overflow-wrap: anywhere; }` 한 줄로 해결.

주소·URL·해시처럼 공백 없는 값을 넣을 때마다 재발하는 종류다.

## 배운 것

- **헤드리스 스크린샷의 폭을 믿지 마라.** 500px 미만은 렌더가 아니라 크롭이다. 좁은 폭
  판정은 iframe 으로만 하고, 의심되면 페이지에 측정 스크립트를 심어 `innerWidth` 를 찍어라.
- **두 소스가 어긋나면 셋째 측정을 만들어라.** 스크린샷과 iframe 이 반대를 말할 때, 둘 중
  하나를 고르는 대신 실제 뷰포트 폭을 직접 출력해서 판정했다.
- **같은 원고를 다시 받으면 읽지 말고 diff 하라.** 3/8 파일만 바뀌었다는 걸 아는 데 몇 초가
  들었고, 케이스 페이지 3개를 건드리지 않아도 된다는 확신이 거기서 나왔다.
- **숫자 전사는 자동으로 대조할 수 있다.** 토큰 다중집합 비교는 눈으로 훑는 것보다 싸고 결정적이다.
- **감쇠 애니메이션이 필요하다고 rAF 루프부터 짜지 마라.** 목표값만 바꾸는 CSS 트랜지션으로
  되는 경우가 많고, 그러면 유지할 상태가 없다.
- **자리표시는 자기가 무엇으로 대체될지 말해야 한다.** 경로를 찍어 두면 교체가 파일 복사로 끝난다.
