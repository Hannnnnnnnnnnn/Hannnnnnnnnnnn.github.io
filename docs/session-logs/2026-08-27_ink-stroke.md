# 2026-08-27 — 커서 잉크 스트로크 (구조를 네 번 갈아엎음)

## 한 줄 요약

커서를 따라 잉크가 번지는 효과를 만들면서 구조를 **원 → 마스크+SVG필터 → 스탬프 비트맵 →
단일 패스**로 네 번 갈아엎었다. 매번 "파라미터를 조절하면 되겠지"로 시작했다가 결국
구조가 원인이었다.

## 왜 네 번이나 바꿨나

각 단계의 실패는 튜닝 부족이 아니라 **그 구조가 원리적으로 낼 수 없는 것**을 요구한 결과였다.

| 구조 | 요구 | 왜 안 됐나 |
|---|---|---|
| 흰 원 + difference | "화면이 깨져 보인다" | 여백 위에서는 반전할 대상이 없어 검은 원이 콘텐츠를 덮음 |
| 마스크 3장이 커서 추적 | "브러시처럼" | `radial-gradient` 는 원만 그린다. 멈추면 세 점이 수렴해 원 하나 |
| SVG 필터(goo + 난류) | "잉크처럼" | 절차적 노이즈는 울퉁불퉁함은 만들어도 붓털은 못 만든다 |
| 붓끝 비트맵 스탬프 | "각지지 않게 / 블러 빼줘" | 비트맵을 겹치면 **겹침의 경계**가 생기고, 그건 블러로만 덮인다 |
| **단일 패스 (현재)** | — | 합집합 경계가 존재하지 않아 블러 없이 선명 |

교훈: **"효과만 가져오고 그 효과가 성립하는 조건은 안 가져오면 깨진다."** 참조로 삼은
noth.in 이 difference 블렌드를 쓸 수 있는 것은 화면이 풀블리드 영상으로 덮여 항상 반전
대상이 있기 때문이고, CodePen 의 브러시 질감은 코드가 아니라 **손으로 그은 것을 찍은 PNG**
에서 나온다(JS 한 줄 없이 `animation: brush 1s` 로 쓸고 지나가는 정적 효과였다).

## 참조 분석

- **noth.in** — 거대 타이포는 텍스트가 아니라 인라인 SVG. Webflow 로 만들었지만 인터랙션은
  Webflow 기능이 아니고(`data-w-id` 0개) 별도 번들(752KB, GSAP + ScrollTrigger + Three.js +
  Lenis). 커서 효과의 정체는 `mask-reveal-canvas` 에서 도는 **ping-pong FBO 유체 셰이더**.
  영상은 GitHub 이 아니라 BunnyCDN 에 별도 호스팅(대역폭 회피).
- **CodePen "Brush Stroke Reveal"** — JS 없음. 브러시 모양 PNG 를 사진 위에 얹고 1초
  CSS 애니메이션으로 쓸고 지나간다.

## 최종 구조

캔버스 하나 + `mix-blend-mode: difference`. 흰 획을 얹으면 흰 배경은 검게, 검은 글자는
희게 뒤집힌다 — 반전판을 만들어 마스크로 뚫던 것과 결과가 같으면서 레이어가 셋 적다.

- 획은 경로 각 점에서 법선으로 반폭만큼 벌린 두 줄을 이은 **닫힌 패스 하나**를 `fill()`
- 폭은 하모닉 4개로 변조 — 고주파가 가장자리를 찢고, 진폭 합이 바닥에 닿으면 잘록해져
  마른 붓 끊김이 된다
- 테이퍼는 **꼬리에만**, 머리에는 반대로 보정(잉크를 머금은 붓)
- 획마다 자기 알파. 손을 멈추면 그 획은 끝나고 다시 움직이면 새 획이 시작된다
- 알파는 **지수 감쇠**로 목표에 접근(올라갈 때 τ=55ms, 내려갈 때 τ=420ms)

성능 부담도 같이 사라졌다 — 프레임당 비트맵 240장 + 전체 캔버스 블러가 `fill()` 한 번이 됐다.

## 측정으로만 잡힌 것들

눈으로는 "대충 되는 것 같다"까지밖에 못 갔고, 아래는 전부 픽셀을 세서 잡았다.

- **획이 끊겨 있었다.** 이벤트가 온 지점에만 찍고 있었는데, `pointermove` 는 빠르게 휘두르면
  50~100px 씩 벌어져 도착한다. 구간 보간을 넣고 **잉크 있는 열 2162개 / 내부 최대 빈 구간
  0px** 로 확인.
- **속도 공식의 나눗셈이 반대였다.** `dt/dist` 를 써서 모든 획이 최대 굵기에 고정돼 있었다.
- **페이드가 꼬리부터 먹히고 있었다.** 균일 페이드면 페이드 중에도 좌우 범위가 유지돼야 한다
  → 측정값 각각 1px 이동.
- **머리가 가늘었다.** 테이퍼가 양 끝 대칭이었다. 고친 뒤 구간 평균 꼬리 61 / 중간 90 /
  머리 111px.
- **옛 획이 되살아났다.** 알파를 공유해서. 공간을 분리해 측정 → 227 → 146 → 122 로 계속 하강.

## 검증기가 나를 속인 사례 (전부 이번 세션)

1. `softRatio 1.000` — 가장자리가 흐린 줄 알았으나 **전역 알파가 내려가 있어서** 나온 값.
2. `edgeTransitionPx 197` — 경계 두께가 아니라 **위에 튄 방울부터 본체까지의 거리**.
3. 한 열만 재서 머리/중간 굵기 비교 — 폭 흔들림 진폭이 더 커서 같은 획에서 94px 과 66px.
4. "아무것도 안 그려짐" — 제품 버그가 아니라 페이지를 재사용해 `running` 이 `true` 로 남은 것.
5. `Math.random() * 0.02` grep 이 `0.028` 을 부분 문자열로 잡아 없는 잔재를 보고.
6. 지연을 넣은 타이밍 테스트가 **스로틀 때문에** 궤적을 전부 만료시켜 `inkPixels: 0`.

→ 5번을 뺀 나머지는 전부 **측정 대상이 아니라 측정 방법의 문제**였다. 결과가 이상하면
코드보다 검사기를 먼저 의심하는 편이 빨랐다.

## 이 환경에서 타이밍 코드를 재는 법

숨은 탭은 rAF 를 안 돌리고 `setTimeout` 도 초 단위로 스로틀한다. 그래서:

    window.requestAnimationFrame = (fn) => { pending = fn; };   // 콜백을 붙잡아 두고
    let t = 5000; performance.now = () => (t += 22);            // 시간을 직접 전진시킨다
    ... 이벤트 발생 ...
    pending(performance.now());                                 // 원하는 만큼만 수동 실행

속도 기반 로직까지 결정적으로 재현된다. **단 매번 새로 로드할 것** — 상태가 남는다.
