## 2. "라이브 카드에 add to cart 가 없다" — 정적 HTML 만 읽고 내린 결론

Dec 01 데모를 만들면서 라이브 PLP HTML 을 받아 카드 마크업을 읽었다.
`.card-information__button` 이 **19개 카드 전부 비어 있었다.** 그래서 케이스 본문의
before/after 블록("swatch selected + hover → add to cart")과 라이브가 어긋난다고
보고하고, 데모에는 버튼을 넣지 않았다.

소유자가 바로잡았다: "스워치를 클릭하고 카드 이미지에 호버하면 애드투카트 버튼이 생겨."

`color-swatches.js` 를 읽으니 그대로였다.

```
스워치 mouseenter
  → colorSwatchFetch(): GET /products/<handle>?variant=<id>&view=card
  → renderProductInfo() → updateButtons(): 비어 있던 .card-information__button 을 채운다
     <add-to-cart class="button button--small">Add to cart</add-to-cart>
  → .card-wrapper:hover .card-information__button .button { opacity:1; transform:translateY(0) }
```

**정적 HTML 은 JS 가 만드는 상태를 말해 주지 않는다.** "슬롯이 비어 있다"는 "기능이 없다"가
아니라 "아직 안 채워졌다"였다. `?view=card` 를 직접 받아 보는 데 30초 걸렸고, 그걸 안 해서
케이스 본문이 틀렸다고 보고까지 했다.

**교훈은 함정 목록의 "검사기를 의심해라"와 같은 계열이되 방향이 반대다** — 그때는 FAIL 을
믿었고, 이번엔 "없다"는 negative 를 믿었다. **없다는 결론은 있다는 결론보다 더 검증이
필요하다.** 초기 마크업, 서버 응답, 실행 중 DOM 은 서로 다른 세 개의 문서다.

## 3. 같은 실수의 연장 — 버튼 색

버튼을 넣을 때 레포에 이미 있던 `.pdp__cta`(흰 배경 / 검은 테두리 / 검은 글자)를 그대로
가져왔다. 그건 **PDP 의 아웃라인 버튼**이고, 카드의 add-to-cart 는 기본 `.button` 이다.

```
--color-base-accent: 12, 12, 12                 → background
--color-base-solid-button-labels: 255, 255, 255 → color
```

**검은 배경에 흰 대문자.** 정반대였다. 이번에는 추론을 그만두고 라이브에서 직접
스워치 → 사진 순으로 호버해 버튼을 띄우고 스크린샷을 찍었다. 그게 유일하게 확실한 확인이었고,
그 김에 호버 효과 두 가지도 그대로 옮겼다:

```css
.button:hover       { background-color: rgba(12,12,12,.85); transition .5s; transition-delay: .25s }
.button:hover:after { animation: shine 1s ease }   /* @keyframes shine { to { left:100% } } */
```

띠는 `skew(-15deg)` 에 **글자색 25%** 그라디언트다. `::after{z-index:-1}` 이 글자를 가리지
않는 이유는 버튼이 `position:relative; z-index:1` 로 쌓임 맥락을 만들기 때문 — 음수
z-index 자식은 그 안에서 **부모 배경 위·내용 아래**에 그려진다. `overflow:hidden` 이 띠를 가둔다.

**레포에 이미 있는 값을 재사용하는 것과 그 값이 여기에도 맞는지 확인하는 것은 다른 일이다.**
`.pdp__cta` 는 "라이브에서 잰 값"이라는 주석까지 달려 있어서 더 믿을 만해 보였다 —
어디서 쟀는지는 안 적혀 있었는데도.

## 5. `[hidden]` 은 클래스 규칙의 `display` 에 진다

Dec 01 데모의 "비워진 우상단" 아웃라인을 `hidden` 속성으로 토글했는데 **항상 보였다.**

```css
.demo .pcard__corner { display: grid; }   /* (0,2,0) — UA 의 [hidden]{display:none} (0,1,0) 를 이긴다 */
```

`.demo .pcard__corner:not([hidden])` 로 걸어 해결. 증상이 고약한 이유는 **토글이 아무 일도
안 하는 것처럼 보이는 게 아니라, 켠 상태가 기본으로 보이기 때문**이다 — JS 를 먼저 의심하게
된다. 실제로 `corner.hidden === true` 를 읽고도 화면에는 있었다. 함정 18 의 또 다른 사례:
속성이 아니라 **무엇이 이기는지**를 봐야 한다.

커진다. 2배면 1258 → 1280 으로 다시 뽑았다(실측 `natural/rendered = 2.04`).

함정 21("소스가 아니라 그 요소의 최대 렌더 폭 × 2")은 맞는데, **"최대"를 데스크톱에서

320~1280 을 훑어 렌더 폭의 최대값을 재라.

같은 이유로 히트맵(`Frame 18.png`, 652x4252)은 **원본 폭 그대로** 두었다 — 세로 1:6.5 라
`.cmp__window`/`.cmp__scroll`(absolute 스크롤러)에 넣지 않으면 행 높이를 통째로 먹는다.
01 Dec 01 에서 이미 겪은 것과 같은 이유고, 같은 컴포넌트로 해결됐다.

## 7. 자동화 탭 함정, 이번에 다시 밟은 것들

전부 `CLAUDE.md` 에 적혀 있는데 매번 다시 만난다. 이번 세션에서 실제로 걸린 순서:

- **`loading="lazy"` 이미지가 안 받아진다** → `naturalWidth: 0`. 호버 컷이 안 바뀐 것처럼
  보였다. `img.loading='eager'` 로 강제.
- **트랜지션이 안 돈다** → 호버 최종 상태의 `opacity` 가 계속 0. 규칙을 주입하고
  `transition:'none'` 을 걸어 **최종 상태를 직접 구성**해서 재야 한다.
- **`getBoundingClientRect()` 는 클리핑을 모른다** → `overflow:hidden` 을 넣고도 rect 는
  그대로 6px 삐져나온 값을 준다. **스크린샷이 판정**이다(실제로 스크린샷으로 잡았다).
- **iframe 이 HTTP 캐시를 쓴다** → `?cb=` 캐시버스터. 그리고 편집 후 탭 자체도
  `location.reload(true)` 가 필요했다(요소가 `null` 로 나와서 알았다).
